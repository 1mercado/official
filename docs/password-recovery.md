Password recovery sends a one-time link directly to the member's registered email using SMTP. It does not require admin approval. Username, email and mobile number can identify an account; an account without an email cannot receive recovery mail. Responses do not disclose whether an account exists. Requests are limited to one link per account per minute. Links expire after 24 hours and can be used once; resetting revokes existing sessions.

Configure SMTP_HOST, SMTP_PORT (587 by default, or 465 for implicit TLS), SMTP_USER, SMTP_PASSWORD and SMTP_FROM as server runtime environment variables in Netlify. Use your email provider's authenticated SMTP server and verified sender. Keep credentials in Netlify settings, never in source control. Deploy after configuring the settings. Confirm delivery using a member account with an inbox you control; open the email, change the password, and verify that the old link and password no longer work. Missing configuration and delivery failures report an error rather than claiming an email was sent.

The admin migration preserves an existing matching account's ID and relationships, or creates the designated account if absent. It stops if the requested username and email belong to separate accounts. It assigns console access exclusively to the designated username and email, sets the requested initial password as a salted scrypt hash once, and revokes prior admin sessions. Later password changes are preserved across deploys.
